What I think you should do

Three things are wrong before any menu question. They are worth fixing in this order.

1 The Reports menu is a leftover stub

/reports renders /api/reports, and that endpoint returns your own email, tenant id and scope list under the label resource: 'reports_data'. The page prints it as raw JSON in a <pre>. It is scaffolding from the original template and has never had data behind it. So the one menu item named Reports is the one place with no reports in it, while 21 real ones sit elsewhere.

Do: make /reports the real home (the artboard on the left), delete the two stub endpoints.

2 Its scope belongs to no role

The route asks for reports:READ / reports:WRITE. No feature in the seed defines either, so no role can ever hold them and only TENANT_ADMIN sees the item at all. This is the same defect that hid the Asset Register behind a 403 for everyone.

Do: drop the invented scope and gate each report on the scope its DATA already uses — TRANSACTIONS:READ for the ledger ones, POS_REPORTS:READ for the POS ones. A manager then sees exactly the reports they can see the data for, with no new feature rows.

3 Two different screens are both called Reports

/frontdesk/reports is not a reports screen — it shows today's live counts: orders open now, tables occupied, customers, feedback. That is a dashboard. Meanwhile the actual reports hub is called Finance and holds twelve tabs, which is already more than a tab row reads well at.

Do: rename /frontdesk/reports to Today (or fold it into the Front Desk dashboard it duplicates), and leave Finance where it is.

The menu I would ship

Group by the question being asked, not by the table the data sits in. A restaurant manager thinks “why are we refunding so much”, not “which of these reads transactionitemdetail”.

One implementation, two entrances
Do not move the reports out of Finance and Returns — rebuilding twelve working tabs to relocate them buys nothing and risks all of it. Reports becomes a catalogue that links into the existing screens with the range and tab already selected (/frontdesk/finance?tab=tenders&preset=today). A manager who lives in Finance keeps their habit; everyone else gets one door and a search box. Nothing is duplicated, so nothing can drift.
